# Prompt Comparison & Retrieval Comparison

Generated by `scripts/generate_comparisons.py` (raw JSON saved to
`state/prompt_comparison.json` and `state/rag_comparison.json`). Required by the
assignment's **Prompt Comparison Rule**: same test set, 2-3 prompt variants, a
comparison table of Prompt → Output → What Improved/Worsened.

## Prompt Variants (Phase 3, before retrieval was added)

| Variant | System Prompt |
|---|---|
| `v1_basic` | "You are a helpful customer support assistant." |
| `v2_role_and_constraints` | Adds role, "only answer using known policy information", "never invent policy details" |
| `v3_role_constraints_concise` | Same as v2 + "keep answers concise, under 3 sentences" |

## Comparison Table (same 3 questions, no retrieval available yet)

| Question | v1_basic | v2_role_and_constraints | v3_role_constraints_concise | What Improved / Worsened |
|---|---|---|---|---|
| "What is your return policy?" | "I don't have specific documentation on that topic... Let me know if you'd like more detail..." | Same refusal-to-guess content | Same refusal, but trimmed to one sentence (no "let me know..." tail) | **No hallucination in any variant** — all three correctly decline to invent a policy. v3 is more concise, but none can actually *answer* the question yet because there is no grounding source. This directly motivated Phase 4 (RAG). |
| "How long does shipping take?" | Same pattern as above | Same | Shorter | Same finding — style differs, capability doesn't, until retrieval is added. |
| "Do you price match competitors?" | Same pattern | Same | Shorter | Confirms all variants avoid fabricating an answer to an out-of-scope question. |

**Insight:** prompt engineering alone controls tone/length and reinforces "don't guess",
but cannot supply facts the model doesn't have. `v2`/`v3` (constraint-heavy prompts) were
selected as the default going forward specifically because they make the "don't fabricate,
escalate if unsure" behaviour explicit — the concrete accuracy gain came from **Phase 4
retrieval**, shown below.

**Default prompt selected:** `v2_role_and_constraints` (concise `v3` is used adaptively,
see Phase 7 feedback-driven switching in `full_agent.py`).

## With vs Without Retrieval (Phase 4)

| Question | Without Retrieval | With Retrieval | Improvement |
|---|---|---|---|
| "What is your return policy?" | "I don't have specific documentation on that topic, so I don't want to guess..." | "Based on our policy documentation: [return_policy] Customers may return most items within 30 days of the delivery date for a full refund..." | Grounded, correct, specific answer instead of a generic non-answer. |
| "Is there a warranty on electronics?" | Generic non-answer | "[warranty_policy] Most electronics products include a 1-year manufacturer warranty covering defects in materials and workmanship..." | Same — real policy content surfaced. |
| "Do you price match competitors?" | Generic non-answer | "[faq] Q: Do you price-match competitors? A: This assistant does not have documentation confirming a price-match policy..." | Retrieval correctly finds the FAQ entry confirming there is *no* such policy — the agent states this precisely instead of refusing vaguely. |

**Conclusion:** retrieval measurably improves both correctness and specificity while
preserving the "don't fabricate" safety property established in Phase 3 — when nothing
relevant is retrieved, the agent still falls back to "I don't have documentation" instead
of guessing (see `docs/03_evaluation_report.md`, TC7).
